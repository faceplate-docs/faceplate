# Кіріспе

Хотфикс — жаңа нұсқа шығармай қатені шұғыл түзету. Одан кейін нұсқа нөмірі өзгермейді: **Қосымша туралы** және `console.log` ішіндегі `faceplate version` жолы бұрынғы нөмірді көрсетеді.

Қате FACEPLATE бағдарламасының өзінде немесе қолданбалы жобада болады. Бағдарлама бір нұсқаның барлық орнатылымдарында бірдей, пайдаланушы оны өзгертпейді. Бағдарламаның браузерде жұмыс істейтін бөлігін frontend, серверде жұмыс істейтін бөлігін backend деп атайды. Қолданбалы жоба — пайдаланушы өз объектісі үшін Studio мен Runtime ортасында жасайтын және өзгертетін барлық нәрсе, мысалы мнемосхемалар мен скриптер.

Сондықтан хотфикстің үш түрі бар:

- frontend хотфиксі мен backend хотфиксі — файлдар және оларды [орнату каталогының](../start_stop/start_stop.md#терминдер-сөздігі) қай бумаларына салу керектігінің сипаттамасы;
- қолданбалы жоба хотфиксі — Studio немесе Runtime ортасында не өзгерту керектігінің сипаттамасы.

Қажетті өзгерістерді енгізуге құқығы бар есептік жазбамен Studio-ға (`http://<сервер>:9000/fp/studio`) және Runtime-ға (`http://<сервер>:9000/fp/runtime`) қолжетімділік қажет. Frontend және backend хотфиксі үшін файлдарды орнату каталогына салу үшін сервердің файлдық жүйесіне (мысалы, SSH арқылы) және түйін консоліне де қолжетімділік қажет.

# Негізгі бөлім

## Хотфикс түрлері

Frontend және backend хотфикстері түйіннің жаңа файлдарды қалай алатынымен ерекшеленеді. Қолданбалы жоба хотфиксі сервердегі файлдарға тимейді. Ешбір хотфикс түйінді тоқтатуды қажет етпейді.

| | Frontend хотфиксі | Backend хотфиксі | Қолданбалы жоба хотфиксі |
|---|---|---|---|
| Нені түзетеді | Бағдарламаның браузердегі бөлігін. Мысалы, Runtime мәзірі ашылмайды немесе Studio терезесінің белгіленімі ығысқан | Бағдарламаның сервердегі бөлігін. Мысалы, репликация деректерді басқа FACEPLATE данасына бермейді | Қолданбалы жобаны. Мысалы, мнемосхемадағы батырма скрипті мәнді басқа тегке жазады |
| Қалай орнатылады | Хотфикс файлдары орнату каталогына салынады | Хотфикс файлдары орнату каталогына салынады және түйін консоліндегі командалармен жүктеледі | Қолданбалы жоба хотфикс сипаттамасы бойынша Studio немесе Runtime ортасында өзгертіледі |
| Түйін түзетуді қалай алады | Түйін интерфейс файлдарын бет әр ашылған сайын орнату каталогынан алады | Түйін жаңа файлдарды консольдегі командалар бойынша, қайта іске қоспай жүктейді | Өзгеріс жобада сақталады |
| Түзету қашан әрекет ете бастайды | Пайдаланушы Studio немесе Runtime бетін жаңартып, қайта кіргенде | Түйін консоліндегі командалардан кейін бірден | Не өзгертілгеніне байланысты |
| Кластер | Файлдар әр түйінде ауыстырылады | Файлдар әр түйінде ауыстырылады және командалар әр түйінде орындалады | Қолданбалы жоба барлық түйіндерге ортақ: түзету бір рет жасалады |

## Frontend хотфиксін орнату

1. Сақтық көшірме жасаңыз. Жоба үшін нұсқалардың бірі — экспорт файлы, [«Жобаны импорттау және экспорттау», «Экспорт» бөлімін](../../project_objects/import_export/import_export.md#экспорт) қараңыз.
2. Хотфикс мұрағаттарын орнату каталогындағы `lib/<модуль-атауы>-<нұсқа>` модуль бумасына ашыңыз: хотфикс сипаттамасында көрсетілгендей `priv` және/немесе `priv/UI` ішіне. Түйінді тоқтатпаңыз.
3. Studio бетін жаңартып, кіріңіз және түзетуді тексеріңіз.
4. Studio және Runtime пайдаланушыларынан бетті жаңартуды сұраңыз: оған дейін браузер бұрынғы файлдармен жұмыс істейді.

Кластерде 1–2 қадамдар әр түйінде орындалады: әр түйін браузерге өз файлдарын береді.

Хотфиксті болдырмау үшін файлдарды сақтық көшірмеден қайтарып, бетті жаңартыңыз.

## Backend хотфиксін орнату

1. Сақтық көшірме жасаңыз. Жоба үшін нұсқалардың бірі — экспорт файлы, [«Жобаны импорттау және экспорттау», «Экспорт» бөлімін](../../project_objects/import_export/import_export.md#экспорт) қараңыз.
2. Хотфикс файлдарын оның сипаттамасындағы бумаларға салыңыз. Модульдің бағдарлама файлдары орнату каталогының `lib/<модуль-атауы>-<нұсқа>/ebin` бумасында жатады.
3. Жұмыс істеп тұрған түйіннің консолінде ([«Түйінді іске қосу және тоқтату», «Түйін консолі» бөлімін](../start_stop/start_stop.md#түйін-консолі) қараңыз) хотфикстің әр модулі үшін орындаңыз:

    ```erlang
    code:load_file(<модуль-атауы>).
    code:purge(<модуль-атауы>).
    <модуль-атауы>:on_init().
    ```

4. Қатенің түзетілгенін тексеріңіз.

Кластерде 1–3 қадамдар әр түйінде орындалады. Түйіндер тоқтатылмайды, Runtime мен Studio үзіліссіз жұмыс істейді.

Хотфиксті болдырмау үшін файлдарды сақтық көшірмеден қайтарып, 3-қадамды қайта орындаңыз.

## Қолданбалы жоба хотфиксі

Қолданбалы жоба хотфиксі хотфикс сипаттамасы бойынша Studio немесе Runtime ортасында орнатылады. Сервер файлдарына қолжетімділік қажет емес, түйін қайта іске қосылмайды. Өзгеріс қашан әрекет ете бастайтыны не өзгертілгеніне байланысты.

1. Жобаны экспорт файлына сақтаңыз, [«Жобаны импорттау және экспорттау», «Экспорт» бөлімі](../../project_objects/import_export/import_export.md#экспорт) қараңыз.
2. Өзгертетін нәрсенің бұрынғы мәндерін жазып қойыңыз.
3. Хотфикс сипаттамасындағы өзгерістерді енгізіп, түзетуді тексеріңіз.

Хотфиксті болдырмау үшін жазылған мәндерді қайтарыңыз.

# Қорытынды

Хотфикс нұсқа нөмірін өзгертпейді және түйінді тоқтатуды қажет етпейді. Frontend және backend хотфикстері алдымен сақтық көшірме жасап, орнату каталогындағы файлдарды ауыстыру арқылы орнатылады: frontend бет жаңартылғаннан кейін, backend түйін консоліндегі командалардан кейін әрекет етеді. Қолданбалы жоба хотфиксі Studio немесе Runtime ортасында орнатылады.
