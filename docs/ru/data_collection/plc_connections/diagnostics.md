# Проверка и диагностика PLC-обмена

[Каталог соединений](./index.md) · [Привязки](./bindings.md)

Faceplate v4.0.7. Последовательно проверяйте конфигурацию, разрешение выполнения, канал и конкретный сигнал.

Работа с окном **Диагностика** и его журналом описана в документе [«Диагностика объектов Runtime»](../../administration/diagnostics/diagnostics.md).

## Карта проверки

| Уровень | Где смотреть | Достаточный результат |
|---|---|---|
| Конфигурация | Повторно открытые соединение и привязка | Сохранены адреса, типы, доступ, преобразование, тег и поле |
| Выполнение | Отключено/Отключить, папка, Runtime, Узел/PID | Разрешено нужное выполнение и есть процесс |
| Канал | Ошибка, Актуальное соединение, внешний участник | Доступен нужный путь и успешна адресованная операция |
| Сигнал | Состояние/error/value привязки и поле тега | Новое известное значение пришло в правильное поле |
| Запись | Ответ и независимое чтение внешней стороны | Получено новое задание после обратной обработки |
| Оборудование | Обратный сигнал или проверка устройства | Подтверждён ожидаемый физический результат |

RUN, OK, PID и старое число по отдельности не подтверждают новые данные. У IEC цикл может читать старый кэш, а TS — относиться к прежнему сообщению. У серверов локальная модель продолжает существовать без внешнего клиента.

## Собрать журнал

1. Выделите сохранённое соединение в **Общий вид → Редактировать** и нажмите **Диагностика**.
2. Выберите **Log level**: info, warning, error или debug. **Log limit** исходно 1000, диапазон 1–100000.
3. Нажмите **Start**, воспроизведите нужное действие и просмотрите **Logs** и **Процессы**.
4. Сохраните сообщения через **Копировать**, зафиксируйте время, путь соединения и привязку. **Очистить** очищает отображаемый вывод.
5. Нажмите **Stop** и закройте окно. Start/Stop управляют сбором сообщений; обменом управляет **Отключено**.

Окно доступно и при STOP. Пустые Logs/Процессы не подтверждают исправность или отсутствие процесса. Полный сетевой кадр и сообщение о каждом успешном запросе в журнале не гарантированы.

## Найти причину

| Симптом | Проверить | Действие и подтверждение |
|---|---|---|
| STOP/no process | Флаги, родители, узел, зависимости | Устранить запрет; затем подтвердить процесс и новое значение |
| timeout/closed/отказ подключения | Адрес с узла выполнения, порт, транспорт, serial-параметры | Восстановить путь; проверить свежую адресованную операцию |
| Один сигнал не работает | Адрес/тип/атрибут, права, выбранные тег и поле | Исправить сигнал; получить новое контрольное значение |
| Значение неверно | Размер, знаковость, порядок, масштаб, тип поля | Сопоставить известное исходное число с расчётом |
| Есть число при потере связи | Default Value, старый кэш/поле, ошибка привязки | Устранить причину и подтвердить новое поступление |
| Запись без результата | Доступ, поддержка драйвера, команда, обратная цепочка | Независимо прочитать внешнюю сторону; проверить обратную связь |
| В списке ОШИБКА, а текст no errors | Флаг, PID, подсказка, поле Ошибка | Оценить реальное выполнение и сигнал; цвет строки не определяет причину |

## Проверить восстановление

1. Зафиксируйте успешное значение A на внешней стороне и в поле.
2. На собственном стенде воспроизведите один отказ: недоступный источник либо неверный адрес. Запишите ошибку конкретной привязки; при наличии контрольного сигнала проверьте его отдельно.
3. Исправьте причину. На источнике установите новое B, отличающееся от A.
4. Подтвердите B внешним средством, затем дождитесь ожидаемого преобразованного B в том же поле Faceplate.
5. Для записи выдайте новое допустимое задание и подтвердите его независимо. W может повторно отправить текущее значение при активации; заранее проверьте его.

Если показание постоянно, используйте независимо наблюдаемый новый запрос/ответ нужного сигнала. Повторная выборка кэша, исчезновение ошибки и старое A не являются проверкой восстановления.
