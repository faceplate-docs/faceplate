# PLC-привязки: подготовка поля и настройка карты сигналов

[Каталог соединений](./index.md) · [Преобразования](./transformation_ru.md) · [Диагностика](./diagnostics_ru.md)

Faceplate v4.0.7. Соединение задаёт общий канал; дочерняя привязка связывает один сигнал с одним полем проекта. Адрес и формат берутся из карты конкретного устройства.

## Подготовить тег и поле

1. Выберите отдельную учебную папку в **Меню → Общий вид**. Определите имя тега, поле, тип и единицы.
2. Используйте подходящий примитив проекта. Если его нет, подготовьте в редакторе примитивов тип с полем **value** и включённым признаком Runtime; создайте экземпляр этого типа в учебной папке. Название поля может отличаться от value.
3. Для дробных измерений и масштабирования выбирайте **float**, для целых и масок — **integer**, для текста — **string**. **bool** используйте только для двух состояний; код 0…3 требует integer.
4. Откройте экземпляр и проверьте, что нужное поле видно и доступно в Runtime. Задайте исходное 0.0 для float, 0 для integer или пустую строку для string. Начальное значение не является результатом чтения.
5. Для W/RW определите допустимое задание до включения привязки. В W оно может отправиться при активации без нового действия оператора.

Пример назначения: папка **PLC_Training**, тег **AnalogValue**, поле **value**, тип float, исходно 0.0. Типы примитивов и права создаёт ответственный за проект; адрес устройства в них не задаётся.

## Создать полную привязку

1. Настройте соединение по его протокольной статье. До окончания подготовки сохраните его с включённым **Отключено**.
2. Откройте соединение двойным щелчком и нажмите **Создать**. Новая привязка должна находиться непосредственно внутри этого соединения.
3. Задайте имя и включите **Отключить**. Заполните адрес, тип и формат по карте сигнала.
4. У **тег** выберите объект проекта. В соседнем списке отдельно выберите поле **value**. Проверьте полный путь и тип поля.
5. Выберите направление по таблице. Если нужен масштаб, задайте его по [инструкции преобразований](./transformation_ru.md).
6. Сохраните, закройте и отдельно откройте объект. Сверьте адрес, тип, направление, преобразование, тег и поле.
7. После подготовки внешнего участника разрешите нужные соединение и привязку. Выполнение проекта, папки и узла также должно быть разрешено.
8. Подтвердите новое значение в выбранном поле; для записи отдельно проверьте внешнюю сторону.

| Доступ | Клиентский драйвер | Серверный драйвер |
|---|---|---|
| R | Устройство → поле Faceplate | Серверная модель → поле; внешний клиент передаёт значение или команду |
| W | Поле → устройство; периодического чтения нет | Поле → серверная модель → внешний клиент |
| RW | Оба направления | Оба направления; начальная публикация зависит от драйвера |

Доступ задаёт направление, а не права. W/RW в общей форме не добавляют запись M-Bus, IEC 62056 или накопленной энергии Mercury. Для серверов направление относительно Faceplate не является запретом внешнему клиенту записывать узел.

## Проверить тип и масштаб

Для учебного числового сигнала используйте исходное 1000 и **Scaling: Factor 0.1, сдвиг 0**. В float-поле ожидается 100.0. Измените источник на 1001: ожидается 100.1. В integer-поле дробная часть округляется.

Если драйвер поддерживает запись, задание 120.0 при этом масштабе соответствует 1200 на внешней стороне. Для серверной публикации применяется обратная цепочка: поле 120.0 публикуется как 1200. Проверяйте именно выбранное направление.

## Настроить альтернативный канал

1. Сначала подтвердите самостоятельную работу основного соединения.
2. Создайте альтернативное соединение того же типа с другой транспортной конфигурацией. В **Главное соединение** у альтернативы выберите основное.
3. Проверьте ссылку и автоматическое отключение самостоятельного выполнения альтернативы. Цепочки главных соединений не создавайте.
4. Карта данных альтернативного пути должна соответствовать привязкам основного соединения. Основное использует свои привязки.
5. На стенде воспроизведите отказ подключения, проверьте **Актуальное соединение** и новое значение. Затем отдельно проверьте возврат основного пути.

Переключение связано с ошибкой подключения; ошибка одного адреса его не гарантирует. SNMP может успешно зарегистрировать недоступного агента, а TCP-шлюз — открыть канал без прибора за ним. У серверов отсутствие клиента само по себе не является отказом локального listener. Сохранённый путь и автоматический возврат к предпочтительному каналу требуют отдельной проверки.

## Перейти от одного сигнала к карте каналов

1. Подготовьте таблицу: имя, внешний адрес, тип, направление, единицы, преобразование, тег и поле.
2. Проверьте одну полную привязку и используйте её как образец. При копировании меняйте адрес и назначение; повторно открывайте копию.
3. Для массовой подготовки используйте **Экспорт .xlsx** из поддерживающего его редактора. Исходный файл экспорта служит шаблоном колонок и форматов; сохраняйте служебные идентификаторы по правилам импорта проекта.
4. Перед импортом сделайте копию конфигурации. Сначала перенесите 10 учебных сигналов в отдельную папку с отключённым выполнением. Выберите правильный контекст импорта.
5. Проверьте отчёт импорта, число объектов, родительские соединения, ссылки на поля, дубли адресов и конкурирующие источники записи. Откройте выборку привязок и сравните с таблицей.
6. Разрешайте обмен после проверки назначений W/RW. Повторите независимый контроль данных.

Наличие команды .xlsx не доказывает, что произвольная книга создаст корректную PLC-карту. Формат экспорта и результат импорта проверяются на используемой сборке.

## Изменить и отключить

**Отключено** останавливает соединение целиком; **Отключить** исключает один сигнал. Сохранение параметров канала может пересоздать его процесс. Отключение сигнала не гарантирует очистку поля; у серверов уже созданный узел может сохраняться до перезапуска.

Перед удалением или переносом проверьте **Перекрёстная ссылка** и назначения полей. После изменения подтвердите новое чтение или запись по [карте проверки](./diagnostics_ru.md).
