# REST API интерфейс

На основе модуля IoT, можно представить два функциональных блока:API доступа к данным (Data Access) — используется для интеграции с внешними системами аналитики (Power BI) и получения истории. Пользовательский API (IoT Server) — создается инженером через iot_http_server_connection для приема произвольных запросов. Ниже представлен проект технического документа.Faceplate: 

# 1. Общие сведения

REST API Faceplate предоставляет интерфейс для обмена данными между ядром системы (Runtime/Historian) и внешними клиентами (BI-системы, ERP, мобильные приложения, веб-порталы). Взаимодействие строится по принципу «Запрос-Ответ» (Request-Response). 

Протокол: HTTP / HTTPS
Формат данных: JSON
Кодировка: UTF-8

## 1.1. Базовый URLАдрес API зависит от конфигурации сервера и настроек безопасности (HTTP/HTTPS):HTTP: http://<Server_IP>:9000/api (Порт по умолчанию)HTTPS: https://<Server_IP>:9443/api(Примечание: Порт может быть изменен в конфигурации Docker контейнера, см. deploy as docker.md).
## 1.2. АутентификацияДля доступа к защищенным ресурсам API необходимо использовать токен авторизации или Basic Auth (в зависимости от настроек модуля безопасности).Заголовок запроса (Header):HTTPAuthorization: Bearer <Your_Access_Token> илиHTTPAuthorization: Basic <Base64_Encoded_Credentials>

API получения исторических данных (History API)Данный раздел описывает стандартный механизм получения агрегированных данных, используемый для интеграции с Microsoft Power BI и другими аналитическими платформами.2.1. Получение исторических трендовEndpoint: /history/read (Примерный путь, требует уточнения в конфигурации конкретного проекта)Method: POSTЗапрос позволяет получить выборку значений по списку тегов за определенный период времени.Тело запроса (Request Payload)Клиент отправляет JSON-объект с параметрами фильтрации:

```JSON
{
  "tags": [
    "StationA.Pump1.Pressure",
    "StationA.Pump1.Flow"
  ],
  "startTime": 1769281200000, 
  "endTime": 1769284800000,
  "aggregation": "1m" 
}
```

tags: Массив ID тегов или их имен в системе.startTime 
endTime: Временные метки в формате Unix Timestamp (ms).
aggregation: (Опционально) Период агрегации (например, "1m", "1h"). Если не указано, возвращаются сырые данные (raw data).Ответ сервера (Response)Сервер возвращает массив объектов с временными метками и значениями.

```JSON
[
  {
    "tag": "StationA.Pump1.Pressure",
    "data": [
      [1769281200000, 24.5, 192], 
      [1769281260000, 24.8, 192]
    ]
  }
]
```

Структура элемента массива данных (см. powerbi_en.md):
Timestamp: Время (Unix ms).Value: Значение.
Quality: Код качества сигнала (192 = Good).

## 3.2. Обработка запросов (Scripting)Логика ответа на запрос программируется через iot_script.При поступлении запроса скрипт получает объект request и должен сформировать response.Пример сценария обработки (Erlang/Script):Принимает JSON, проверяет поле "cmd" и записывает значение в тег.Erlang% Входные данные: Message (содержит тело запроса) RequestData = json:decode(Message),

```erlang
Result = case maps:get("cmd", RequestData) of
    "set_setpoint" -> 
        Val = maps:get("value", RequestData),
        faceplate:write_tag("Tag_Setpoint", Val),
        #{status => "ok", written => Val};
    _ -> 
        #{status => "error", reason => "unknown command"}
end,

Response = json:encode(Result).
```

# 4. Коды состояния HTTPПри работе с API используются стандартные коды ответа:

200 OK — Запрос выполнен успешно.
204 No Content — Успешно, но нет данных для возврата (часто используется при записи в InfluxDB/IoT).
400 Bad Request — Ошибка в синтаксисе запроса (неверный JSON, отсутствуют обязательные поля).
401 Unauthorized — Ошибка аутентификации (неверный токен).
500 Internal Server Error — Внутренняя ошибка сервера Faceplate.

# 5. Рекомендации по интеграцииВременные зоны: 

Faceplate обрабатывает запросы, используя временную зону сервера. Рекомендуется передавать и принимать время в формате UTC (Unix Timestamp), чтобы избежать смещений. Пакетная передача: 
    - При запросе больших объемов исторических данных (например, для Power BI) избегайте запросов за период более 30 дней с детализацией "raw". Используйте агрегацию (среднее за час/день).
    - Безопасность: При использовании iot_http_server_connection в публичных сетях обязательно настраивайте SSL-сертификаты (поля Key и Certificate в настройках соединения).
