# Глоссарий

| Термин | Значение |
|---|---|
| Пользователь | Учётная запись для входа в Studio и Runtime: логин, пароль, роли и права на мнемосхемы |
| Роль | Именованный набор прав на мнемосхемы. Пользователь получает права всех своих ролей. Подробно — в документе [«Роли и права доступа»](roles.md) |
| Личные права | Права на мнемосхемы, выданные самому пользователю, а не через роль |

# Введение

Пользователь FACEPLATE — учётная запись, под которой человек входит в Studio или Runtime. В ней хранятся логин и пароль, контактные данные, роли и личные права на мнемосхемы. От ролей и прав зависит, какие мнемосхемы человек видит в Runtime и может ли менять на них значения.

Раздел находится в главном меню Studio: **Права** → **Пользователи**.

Сквозной пример — оператор смены `ivanov` с ролью `shift_operators`.

Понадобится доступ к Studio (`http://<сервер>:9000/fp/studio`) под учётной записью с правом изменять проект.

# Основная часть

## Список пользователей

Слева — список пользователей проекта, над ним кнопки удаления (корзина) и создания (**+**) и строка поиска. Поиск находит пользователей, чей логин начинается с введённой строки. Ищется строка от трёх символов, более короткая показывает весь список. Встроенные учётные записи `system` и `admin` в списке не показываются.

Щелчок по пользователю открывает справа его карточку.

## Создание пользователя

Нажмите **+**, в окне «Задайте имя» введите логин и нажмите **ОК**.

Новый пользователь сразу может войти: его пароль совпадает с логином, роль — `operators`, личных прав нет. Откройте карточку, задайте пароль, роли и права и сохраните.

## Карточка пользователя

![Карточка пользователя](images/users_01_user.png)

| Поле | Назначение |
|---|---|
| **Логин** | Имя для входа |
| **Пароль**, **Подтверждение пароля** | Новый пароль, см. [Пароль](#пароль). Пустые поля оставляют пароль прежним |
| **Роли** | Роли пользователя, см. [Роли пользователя](#роли-пользователя) |
| **Ограничение памяти (МБ)** | Предел памяти, который сервер выделяет сеансу пользователя. Пусто — предел по умолчанию сервера |
| **Email** | Адрес в формате `name@server.com` |
| **Телефон** | 11 цифр, можно с `+` в начале. Несколько номеров перечисляются через запятую |

Таблица под полями — права пользователя на мнемосхемы: собственные (**Права**), полученные через ссылки (**Внешние ссылки**) и через роли (**Ролевые**). Изменить можно только колонку **Права**, остальные показывают итог. Смысл колонок — в документе [«Роли и права доступа», раздел «Права на мнемосхемы»](roles.md#права-на-мнемосхемы).

**Сохранить** записывает изменения, **Отмена** и стрелка слева от заголовка закрывают карточку без записи.

## Пароль

Требования к паролю:

- не короче 6 символов;
- только латинские буквы, цифры и символы `!@#$%^&*_-`;
- есть хотя бы одна строчная и одна заглавная буква, цифра и символ из списка выше.

Поле **Подтверждение пароля** становится доступным, когда пароль отвечает требованиям. Если подтверждение не совпадает с паролем, по **Сохранить** появляется сообщение о несовпадении паролей и пароль не меняется.

Пример: `Demo_123`.

## Роли пользователя

В списке **Роли** отметьте роли пользователя. Пользователь получает права всех отмеченных ролей вместе со своими личными правами.

Роль `operators` есть у каждого пользователя: если снять её, после сохранения она возвращается. Поэтому права, выданные роли `operators`, получают все пользователи.

Чтобы пользователь мог работать в Studio, дайте ему роль `.administrators`. Остальные роли создаются в разделе **Права** → **Роли**, см. документ [«Роли и права доступа»](roles.md).

В примере у `ivanov` роли `operators` и `shift_operators`, а личные права — чтение и запись на `/mnemo_demo`.

## Вход в Studio и Runtime

Вход один и тот же для Studio (`http://<сервер>:9000/fp/studio`) и Runtime (`http://<сервер>:9000/fp/runtime`): логин и пароль из карточки.

Studio открывается только пользователям с ролью `.administrators`. Остальным после входа показывается сообщение об отсутствии доступа.

Runtime открывается любому пользователю. В меню **Мнемосхемы** он видит только мнемосхемы, на которые у него есть права, см. [«Роли и права доступа», раздел «Что видит пользователь в Runtime»](roles.md#что-видит-пользователь-в-runtime).

## Удаление пользователя

Выделите пользователя, нажмите корзину и подтвердите **yes**.

# Заключение

Порядок работы:

1. **Права** → **Пользователи** → **+** → логин → **ОК**.
2. В карточке задайте пароль по требованиям, роли и, при необходимости, личные права на мнемосхемы. **Сохранить**.
3. Для работы в Studio добавьте роль `.administrators`.
4. Проверьте результат: войдите под пользователем в Runtime и откройте **Мнемосхемы**.
