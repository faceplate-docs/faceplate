# Модели прогнозирования

> **Статус:** Черновик — структуры данных ниже взяты из реальных экспортов проектов; интерфейс настройки и процесс обучения должна описать команда Faceplate.

В состав Faceplate входят модели машинного обучения, прогнозирующие
технологические величины (например, потребление электроэнергии и мощности
объекта) по архивной истории и дополнительным внешним данным. Модели
находятся в дереве проекта и управляются через объект **model control**
(`prototype@model_control`).

## Идентификация модели

Каждая модель идентифицируется полным путём в дереве проекта. Путь —
уникальный ключ модели, используемый везде, где на неё ссылаются.

```
/PROJECT/KAZ/REGION/OBJECT/...
 │        │   │      └── объект (площадка, подстанция, завод …)
 │        │   └───────── регион
 │        └───────────── уровень страны (в старых проектах может отсутствовать)
 └────────────────────── проект
```

В старых проектах уровень страны отсутствует: `/PROJECT/REGION/OBJECT/...`.
При сопоставлении путей между старыми и новыми проектами сегмент `/KAZ/`
нужно убирать.

## Атрибуты модели

| Атрибут | Описание |
|---|---|
| Путь | Уникальный ключ, см. выше. |
| Название | Человекочитаемое имя. |
| Тип | Что прогнозируется, например мощность или электроэнергия. TODO: полный список типов. |
| `disabled` | Отключена ли модель. Логическое значение (`:atom:true` / `:atom:false` в текущих экспортах). Отключённые модели не обучаются и не исполняются. |
| `input` | Исторические входные сигналы в виде адресов `fp://`. В старых проектах колонка называется `historical [input]`. |
| `configuration` | JSON с настройками по горизонтам, см. ниже. |
| `state` | JSON со статусом работы и метриками качества по горизонтам, см. ниже. |

## Входные данные

Модель принимает один или несколько входов:

| Вход | Роль | Описание |
|---|---|---|
| Исторический сигнал | обязательный | Архивные значения прогнозируемой величины по адресу `fp://`, например `fp://PROJECT/REGION/OBJECT/SIGNAL`. См. [Архивы](<../Архивы и Тренды.md>). |
| Погода | feature (признак) | Погодные данные по местоположению объекта, используются как дополнительный признак. |
| Ремонтные заявки | regressor (регрессор) | Плановые заявки на ремонт / обслуживание, используются как регрессор. |

## Горизонты и конфигурация

Модель может прогнозировать на трёх горизонтах: `day`, `month` и `year`.
Каждый горизонт настраивается независимо в JSON `configuration`:

```json
{
  "day":   { "model_path": "xgb/...",     "input_range": 604800,  "output_range": 86400 },
  "month": { "model_path": "prophet/...", "input_range": 7776000, "output_range": 2592000 },
  "year":  { "model_path": "prophet/...", "input_range": 94608000, "output_range": 31536000 }
}
```

| Поле | Описание |
|---|---|
| `model_path` | Алгоритм и расположение модели. Первый сегмент пути — название алгоритма: `xgb` (градиентный бустинг) или `prophet` (декомпозиция временного ряда). TODO: полный список алгоритмов и смысл остальной части пути. |
| `input_range` | Длина истории для обучения / инференса, в секундах. |
| `output_range` | Длина прогноза, в секундах (например, `86400` = 1 сутки). |

## Состояние и качество прогноза

JSON `state` хранит статус работы по каждому горизонту:

```json
{
  "day":   { "status": "COMPLETE", "avg_fact": 1234.5, "avg_fore": 1250.1, "bias": 0.0126 },
  "month": { "status": "IDLE" },
  "year":  { "status": "ERROR" }
}
```

| Поле | Описание |
|---|---|
| `status` | `COMPLETE` — прогноз построен; `IDLE` — ещё не запускалась / ожидает; `ERROR` — последний запуск завершился ошибкой. |
| `avg_fact` | Среднее фактическое значение за окно оценки. |
| `avg_fore` | Среднее прогнозное значение за то же окно. |
| `bias` | Систематическая ошибка прогноза. TODO: точная формула и знак. |
