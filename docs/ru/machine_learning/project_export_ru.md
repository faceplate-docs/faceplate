# Экспорт проекта

> **Статус:** Черновик — формат ниже взят из реальных экспортов; процедуру экспорта в интерфейсе должна описать команда Faceplate.

Проект Faceplate можно выгрузить в книгу Excel с именем
`faceplate_project-<N>.xlsx`, где `<N>` — номер проекта. Экспорт — обычный
способ просмотреть сразу все модели прогнозирования проекта.

## Структура книги

| Лист | Содержимое |
|---|---|
| `prototype@model_control` | Одна строка на модель прогнозирования (обязателен). |
| `Лист1` | Необязательный список моделей, использующих погоду (путь модели во второй колонке). |
| `Лист2` | Необязательный список моделей, использующих ремонтные заявки (путь модели во второй колонке). |

`Лист1` и `Лист2` присутствуют не всегда; если в новом экспорте их нет,
списки из более старого экспорта того же проекта остаются актуальными.

## Колонки листа `prototype@model_control`

| Колонка | Текущий формат | Старый формат |
|---|---|---|
| Путь модели (ключ) | `prototype@model_control` | `prototype@model_control` |
| Исторические входы | `input` | `historical [input]` |
| Признак отключения | `:atom:true` / `:atom:false` | `True` / `False` |
| `configuration` | JSON, см. [Модели прогнозирования](forecasting_models_ru.md) | то же |
| `state` | JSON со статусом и метриками по `day` / `month` / `year` | отсутствует |
| `icon`, `nodes` | Большие вспомогательные колонки; при анализе можно пропускать | то же |

Пути в `Лист1` / `Лист2` записаны в короткой форме `/PROJECT/REGION/...`, а в
основном листе — `/PROJECT/KAZ/REGION/...`. Перед сопоставлением удалите
сегмент `/KAZ/`.

## Типичные виды анализа

- Список моделей с регионом, объектом, типом, статусом и входами.
- Какие модели используют погоду или ремонтные заявки.
- Алгоритмы по горизонтам (`xgb` / `prophet` × `day` / `month` / `year`).
- Диапазоны горизонтов прогноза (`output_range`: мин / макс / медиана).
- Покрытие: объекты, у которых есть модели и мощности, и электроэнергии, только одна из них или ни одной.
- Качество прогноза по горизонтам из колонки `state`.
