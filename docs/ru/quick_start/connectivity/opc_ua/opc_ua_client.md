# Faceplate

# Быстрый старт: Faceplate (OPC UA клиент) → OPC UA сервер

# Введение: Интеграция через OPC UA

Данный раздел описывает концепцию и практические шаги по организации обмена данными в среде **Faceplate**. В качестве практического примера рассматривается сценарий получения данных из внешней системы с использованием промышленного стандарта **OPC UA**.

## Архитектура решения

В рамках руководства реализуется следующая цепочка передачи данных:

- **Источник (Server):** Стороннее ПО или контроллер (в примере - _Prosys OPC UA Simulation Server_), имитирующий работу технологического оборудования.
- **Приемник (Client):** Платформа **Faceplate**, которая подключается к источнику, считывает значения переменных и сохраняет их в собственную базу данных (историю).

В качестве источника данных в примере используется сервер симуляции - [Prosys OPC UA Simulation server](https://prosysopc.com/products/opc-ua-simulation-server/). Сервер симуляции предназначен для тестирования OPC UA клиентов, соединений и информационных моделей.

Prosys OPC UA Simulation Server includes predefined simulation signals that can be connected to any variable and let you simulate data of real equipment, especially with the help of Information Models. The signals also provide simulation of data history according to OPC UA specifications.

## Цель руководства

К концу изучения раздела вы научитесь:

- Конфигурировать транспортный канал (Connection) для связи с внешним сервером.
- Создавать привязки (Bindings) для конкретных технологических параметров.
- Настраивать архивацию полученных данных для последующего анализа и визуализации в интерфейсе оператора (**Runtime**).

# Необходимые шаги по реализации интеграции

## Подготовка Prosys Simulation Server

Перед настройкой в Faceplate запустите Prosys Simulation Server и зафиксируйте следующие данные на вкладке **Status**:

- **Connection Address (Endpoint URL):** Обычно это opc.tcp://\[ИМЯ_ПК\]:53530/OPCUA/SimulationServer.
- **Security Policy:** Для первого теста выберите None (если настройки сервера позволяют).

## Создание соединения в Faceplate (Connection)

Создайте новое соединение типа plc_opcua_client_connection.

### **Настройки (Settings):**

- **Endpoint URL:** Вставьте URL, скопированный из Prosys (например, opc.tcp://192.168.1.10:53530/OPCUA/SimulationServer).
- **Security Mode:** Выберите None (согласно настройкам сервера для упрощенного теста).
- **User Identity:** Выберите Anonymous (Prosys Simulator по умолчанию разрешает анонимный вход).
- **State:** Переведите в **RUN**.

**Диагностика:** Если статус изменился на **RUN** и поле **Error** пустое, значит, Faceplate успешно установил сессию с Prosys.

## Настройка привязки данных (Binding)

Теперь необходимо выбрать данные, которые мы хотим получать. Prosys Simulation Server генерирует случайные значения (синусоиды, пилы и т.д.).

### Как найти адрес узла (NodeId)

В Prosys перейдите на вкладку **Address Space**. Найдите, например, переменную Sawtooth (Пила):

- Она обычно находится в папке: Objects -> StaticData -> Sensors.
- Её **NodeId** будет выглядеть примерно так: ns=3;s=Sawtooth или ns=3;i=1001.

### Настройка в Faceplate

Создайте объект plc_opcua_client_binding внутри вашего соединения:

- **Name:** Prosys_Sawtooth
- **Tag:** Выберите тег в Faceplate, куда будут записываться данные (например, Global.Sensors.SawtoothValue).
- **OPC tag (NodeId):** Вставьте адрес из Prosys: ns=3;s=Sawtooth.
- **Access:** Установите R (Чтение).
- **Sampling Interval:** Укажите, как часто опрашивать сервер (например, 1000 мс).

### Использование функции Browse

Если вы не знаете точный NodeId, в интерфейсе Faceplate при настройке привязки (Binding) воспользуйтесь кнопкой **Browse**:

- Нажмите кнопку вызова дерева узлов.
- Faceplate подключится к Prosys и отобразит иерархию папок сервера.
- Просто выберите нужную переменную кликом - NodeId подставится автоматически.

## Особенности при работе с Prosys

- **Сертификаты:** Если вы решите использовать шифрование (SignAndEncrypt), после первой попытки подключения Faceplate в Prosys Simulation Server нужно перейти на вкладку **Certificates** и переместить сертификат Faceplate из списка "Rejected" (Отклоненные) в "Trusted" (Доверенные).
- **Типы данных:** Prosys передает Sawtooth и Sinusoid как тип Double. Убедитесь, что ваш тег в Faceplate поддерживает вещественные числа.

## Итог

После перевода привязки в состояние **RUN**, значение в теге Faceplate начнет обновляться в соответствии с графиком «пилы» из симулятора. Это подтверждает корректность настройки обмена.
