# Архивы

> Тип: инструкция · Статус: черновик

Как настроить историзацию сигналов и читать архивы.

Подсистема «Архивы» хранит значения, поступающие из внешних источников (PLC-соединения, IoT-соединения, результаты работы скриптов). Накопленная история используется операторами и инженерами для анализа и мониторинга процессов: на трендах, в отчётах и через API. Как оператор работает с трендами, описано в [Тренды и архивы](../operator/trends.md).

## Объект архива и источник значения

Архив — это объект проекта, который описывает один архивируемый параметр: откуда берётся значение, как часто и как долго оно хранится. Все архивы проекта собраны в редакторе «Архивы» (Studio): на главной панели отображается база архивов со статусами и источниками, здесь же архивы создаются, редактируются и удаляются.

Свойства подсистемы, которые важно учитывать при проектировании:

- **Цикличность.** Значения записываются циклически через заданный период, независимо от скорости изменения параметра. Дополнительно запись фильтруется минимальным шагом (см. ниже).
- **Глубина хранения.** Данные хранятся заданное число дней, затем вытесняются.
- **Сжатие.** Точки хранятся в сжатом виде для экономии диска и ускорения чтения.
- **Поиск и доступ.** История доступна на трендах, в выгрузках и через [API архивов](api/archives-api.md).
- **Защита.** Обеспечивается целостность данных и защита от несанкционированных изменений.
- **Развёртывание.** Архивы могут храниться локально или на удалённом узле.

Источник значения задаётся полем «Источник»:

| Источник | Откуда берётся значение |
|---|---|
| `tag` | Значение поля тега (объекта) проекта |
| `script` | Результат скрипта, который вычисляет значение из одной или нескольких переменных |
| `iot` | Значение, полученное через IoT-соединение |

Тип хранимого значения задаётся полем «Тип данных»:

| Тип данных | Назначение |
|---|---|
| `simple` | Основной тип для непрерывно меняющихся параметров (давление, температура, мощность) |
| `categorized` | Коды состояний объекта: дискретные значения, для которых важен факт смены состояния |
| `counter` | Счётчики: в архив записывается разница между предыдущим и текущим значениями |

## Создание архива для сигнала

1. Откройте редактор «Архивы».
2. Нажмите кнопку создания нового архива или выберите существующий для редактирования. Откроется форма конфигурации.
3. Заполните параметры:

   | Параметр | Описание |
   |---|---|
   | «Имя» | Уникальное имя архива в рамках проекта. Обычно отражает содержимое, например «Давление». Под этим именем архив виден операторам в окне выбора трендов. |
   | «Папка» | Расположение архива в структуре проекта. |
   | «Отключен» | Переключатель: если включён, в режиме исполнения запись в архив не ведётся. |
   | «Глубина (дней)» | Длина хранимой истории. Минимум — 1 день. Увеличение глубины пропорционально увеличивает требования к дисковому пространству. |
   | «Период (мс)» | Частота записи значений. Уменьшение периода увеличивает нагрузку на ЦПУ и объём данных на диске. |
   | «Минимальный шаг» | Новое значение записывается, только если оно отличается от предыдущего записанного на величину, большую или равную шагу. Позволяет отсечь «шум» и снизить нагрузку. |
   | «Источник» | `tag`, `script` или `iot` (см. выше). |
   | «Тип данных» | `simple`, `categorized` или `counter` (см. выше). |

4. Для источника `tag` или `iot` укажите тег или соединение, из которого берётся значение. Для источника `script` настройте скрипт, как описано ниже.
5. Сохраните архив. Он появится в базе архивов с текущим статусом.

### Источник `script`

Источник `script` позволяет обработать архивируемое значение или вычислить его из нескольких входных параметров.

Принцип работы:

1. Подсистема архивирования считывает значения полей тегов, к которым привязаны переменные скрипта.
2. Скрипт вызывается с картой значений переменных на входе.
3. Возвращённое скриптом значение записывается в архив.

Настройка:

1. В форме архива выберите язык скрипта: **Erlang** или **JavaScript**.
2. Добавьте переменные и для каждой укажите источник значения (поле тега).
3. Введите текст скрипта, который возвращает одно значение.
4. Нажмите кнопку компиляции. Если ошибок нет, редактор выведет подтверждение; иначе исправьте скрипт по сообщению об ошибке.

## Экспорт и импорт конфигурации архивов

Базу архивируемых параметров можно выгрузить в файл `.xlsx` и загрузить обратно. Это используется для переноса настроек между проектами (например, с тестового сервера на рабочий) и для массового редактирования в табличном редакторе.

**Экспорт.** В редакторе «Архивы» нажмите кнопку экспорта. В файле каждая строка соответствует одному архиву и содержит:

- место хранения и имя архива;
- период архивирования и глубину хранения;
- состояние (включён или отключён);
- тип источника и ссылку на тег или скрипт;
- минимальный шаг и тип данных.

**Импорт.** Нажмите кнопку импорта и выберите файл. Система загрузит строки в базу архивов. Если данные несогласованны (например, указанный тег отсутствует в проекте), выводится сообщение об ошибке с номером строки и причиной; исправьте файл и повторите импорт.

> **Внимание.** Перед импортом в рабочий проект проверьте, что все теги и папки, на которые ссылается файл, существуют. Импорт с ошибками прерывается на первой несогласованной строке.

## Особенности и ограничения

- Глубина хранения не может быть меньше 1 дня.
- Период и глубина напрямую определяют нагрузку: диск растёт пропорционально глубине и обратно пропорционально периоду, ЦПУ нагружается тем сильнее, чем короче период.
- Минимальный шаг отсекает изменения меньше заданной величины. Для `categorized` и `counter` задавайте его с учётом смысла значения: слишком большой шаг скроет смену состояния или приращение счётчика.
- Имя архива видно операторам: называйте архивы по содержимому, а не по техническому адресу тега.
