# Введение

Хотфикс — срочное исправление ошибки без выпуска новой версии. Номер версии после него не меняется: **О приложении** и строка `faceplate version` в `console.log` показывают прежний номер.

Ошибка бывает в самой программе FACEPLATE или в прикладном проекте. Программа одинакова во всех установках одной версии, пользователь её не меняет. Часть программы, которая работает в браузере, называют frontend, а часть, которая работает на сервере, — backend. Прикладной проект — всё, что пользователь создаёт и меняет в Studio и Runtime под свой объект, например мнемосхемы и скрипты.

Поэтому хотфикс бывает трёх видов:

- хотфикс frontend и хотфикс backend — файлы и описание, в какие папки [каталога установки](../start_stop/start_stop.md#глоссарий) их положить;
- хотфикс прикладного проекта — описание, что изменить в Studio или Runtime.

Понадобится доступ к Studio (`http://<сервер>:9000/fp/studio`) и Runtime (`http://<сервер>:9000/fp/runtime`) под учётной записью с правом вносить нужные изменения. Для хотфикса frontend и backend — ещё доступ к файловой системе сервера (например, по SSH), чтобы положить файлы в каталог установки, и к консоли узла.

# Основная часть

## Виды хотфикса

Хотфиксы frontend и backend различаются тем, как узел получает новые файлы. Хотфикс прикладного проекта не трогает файлы на сервере. Ни один хотфикс не требует остановки узла.

| | Хотфикс frontend | Хотфикс backend | Хотфикс прикладного проекта |
|---|---|---|---|
| Что исправляет | Часть программы в браузере. Например, не открывается меню Runtime или съехала разметка окна Studio | Часть программы на сервере. Например, репликация не передаёт данные в другой экземпляр FACEPLATE | Прикладной проект. Например, скрипт кнопки на мнемосхеме пишет значение не в тот тег |
| Как ставят | Файлы хотфикса кладут в каталог установки | Файлы хотфикса кладут в каталог установки и загружают командами в консоли узла | Прикладной проект меняют в Studio или Runtime по описанию хотфикса |
| Как узел получает исправление | Узел берёт файлы интерфейса из каталога установки при каждом открытии страницы | Узел загружает новые файлы по командам в консоли, без перезапуска | Изменение сохраняется в проекте |
| Когда исправление начинает действовать | Когда пользователь обновит страницу Studio или Runtime и войдёт снова | Сразу после команд в консоли узла | Зависит от того, что изменено |
| Кластер | Файлы заменяют на каждом узле | Файлы заменяют и команды выполняют на каждом узле | Прикладной проект общий для всех узлов: правку делают один раз |

## Установка хотфикса frontend

1. Сделайте резервную копию. Один из вариантов для проекта — файл экспорта, см. [«Импорт и экспорт проекта», раздел «Экспорт»](../../project_objects/import_export/import_export.md#экспорт).
2. Распакуйте архивы хотфикса в папку модуля `lib/<название-модуля>-<версия>` каталога установки: в `priv` и/или в `priv/UI`, как указано в описании хотфикса. Узел не останавливайте.
3. Обновите страницу Studio, войдите и проверьте исправление.
4. Попросите пользователей Studio и Runtime обновить страницу: до этого браузер работает с прежними файлами.

В кластере шаги 1–2 выполняют на каждом узле: каждый узел отдаёт браузеру свои файлы.

Чтобы отменить хотфикс, верните файлы из резервной копии и обновите страницу.

## Установка хотфикса backend

1. Сделайте резервную копию. Один из вариантов для проекта — файл экспорта, см. [«Импорт и экспорт проекта», раздел «Экспорт»](../../project_objects/import_export/import_export.md#экспорт).
2. Положите файлы хотфикса в папки из его описания. Файлы программы модуля лежат в папке `lib/<название-модуля>-<версия>/ebin` каталога установки.
3. В консоли работающего узла (см. [«Запуск и остановка узла», раздел «Консоль узла»](../start_stop/start_stop.md#консоль-узла)) выполните для каждого модуля из хотфикса:

    ```erlang
    code:load_file(<название-модуля>).
    code:purge(<название-модуля>).
    <название-модуля>:on_init().
    ```

4. Проверьте, что ошибка исправлена.

В кластере шаги 1–3 выполняют на каждом узле. Узлы не останавливают, Runtime и Studio работают без перерыва.

Чтобы отменить хотфикс, верните файлы из резервной копии и снова выполните шаг 3.

## Хотфикс прикладного проекта

Хотфикс прикладного проекта ставят в Studio или Runtime по описанию хотфикса. Доступ к файлам сервера не нужен, узел не перезапускают. Когда изменение начинает действовать, зависит от того, что изменено.

1. Сохраните проект в файл экспорта, см. [«Импорт и экспорт проекта», раздел «Экспорт»](../../project_objects/import_export/import_export.md#экспорт).
2. Запишите прежние значения того, что меняете.
3. Внесите изменения из описания хотфикса и проверьте исправление.

Чтобы отменить хотфикс, верните записанные значения.

# Заключение

Хотфикс не меняет номер версии и не требует остановки узла. Хотфиксы frontend и backend ставят заменой файлов в каталоге установки, сделав перед этим резервную копию: frontend действует после обновления страницы, backend — после команд в консоли узла. Хотфикс прикладного проекта ставят в Studio или Runtime.
