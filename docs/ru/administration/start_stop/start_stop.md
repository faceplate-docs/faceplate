# Глоссарий

| Термин | Значение |
|---|---|
| Узел | Один запущенный сервер FACEPLATE. Имя узла имеет вид `fp@<сервер>`, см. [«Узлы кластера»](../nodes/nodes.md) |
| Каталог установки | Папка на сервере, в которую установлен FACEPLATE. В ней лежат папки `bin`, `erts-<версия>`, `etc`, `lib` и `releases`. После первого запуска в ней появляются папка `logs` и база `DB`, после запуска в фоне — папка `log`, а после подключения модуля Git к репозиторию — папка `cvs` |
| Консоль узла | Командная строка работающего узла, в которой выполняют команды |

# Введение

Узел запускают и останавливают командами в терминале сервера (например, по SSH). Команды выполняют из папки, в которой лежит каталог установки `faceplate`. Полный список команд выводит `./faceplate/bin/faceplate` без параметров.

Узел запускают в окне терминала или в фоне. От этого зависит, что будет с узлом, когда окно закроют, и как открыть его консоль.

# Основная часть

## Предел открытых файлов

Узел работает, только если процессу разрешено открыть не меньше 200 000 файлов. Предел задают командой `ulimit -n` в том же терминале перед запуском:

```bash
ulimit -n <предел>
```

`<предел>` — число от 200 000. Команда действует только в этом терминале, поэтому её повторяют перед каждым запуском.

Если предел меньше, процесс узла запускается, но FACEPLATE не работает: Studio не открывается, а строка `ulimit <текущий> is less than minimum 200000` появляется в `logs/console.log`, `logs/error.log` и там, где видны сообщения запуска: в окне терминала (запуск в окне) или в `log/erlang.log.<номер>` (запуск в фоне). Остановите узел (см. [«Остановка»](#остановка)), задайте предел и запустите снова.

## Запуск в окне и в фоне

| | В окне (`console`) | В фоне (`daemon`) |
|---|---|---|
| Где видны сообщения запуска | В окне терминала | В файле `log/erlang.log.<номер>` каталога установки |
| Консоль узла | Открыта в этом окне | Открывают командой `remote_console`, см. [«Консоль узла»](#консоль-узла) |
| Окно терминала или сеанс SSH закрыли | Узел останавливается | Узел продолжает работу |

Ошибки при любом способе запуска пишутся в журналы сервера, см. [«Журналы сервера»](../logs/logs.md).

## Запуск в окне

```bash
ulimit -n <предел>
./faceplate/bin/faceplate console
```

Окно занято узлом. Не закрывайте его и не разрывайте сеанс SSH, пока узел должен работать.

## Запуск в фоне

```bash
ulimit -n <предел>
./faceplate/bin/faceplate daemon
```

Команда сразу возвращает терминал, узел запускается в фоне.

## Проверка запуска

Узел запущен, когда:

- в окне терминала (запуск в окне) или в `log/erlang.log.<номер>` (запуск в фоне) появилась строка `----------------FACEPLATE STARTED----------------------------`;
- открывается Studio: `http://<сервер>:9000/fp/studio`.

Команда `./faceplate/bin/faceplate ping` отвечает `pong`, если процесс узла работает, и `Node is not running!`, если нет. `pong` ещё не значит, что FACEPLATE работает: при малом пределе открытых файлов узел тоже отвечает `pong`.

## Консоль узла

У узла, запущенного в окне, консоль открыта в этом окне. К узлу, запущенному в фоне, консоль подключают из другого терминала:

```bash
./faceplate/bin/faceplate remote_console
```

Каждую команду вводят целиком, вместе с точкой в конце, и нажимают Enter.

Чтобы выйти из `remote_console`, не останавливая узел, нажмите Ctrl+G, введите `q` и нажмите Enter. Команда `q().` останавливает сам узел.

## Остановка

```bash
./faceplate/bin/faceplate stop
```

Команда работает для узла, запущенного и в окне, и в фоне. Узел запущен в окне — выполните её в другом терминале. Команда завершается, когда узел остановлен; после этого `ping` отвечает `Node is not running!`.

## Запуск в кластере

Узлы кластера запускают и останавливают теми же командами, что и отдельный узел. Переменная при запуске нужна в двух случаях: узел впервые присоединяют к кластеру или кластер запускают после остановки всех узлов. Перед этими командами тоже задают [предел открытых файлов](#предел-открытых-файлов). Что настроить на серверах, чтобы узлы соединились в кластер, см. [«Хранилища», раздел «Подготовка серверов»](../../data_storage/storage/storage.md#подготовка-серверов).

### Присоединение узла к кластеру

Присоединяют узел с пустой папкой `DB` в каталоге установки: новую установку или узел, папку `DB` которого удалили. Его первый раз запускают с переменной `ATTACH_TO` — именем работающего узла кластера:

```bash
ulimit -n <предел>
env ATTACH_TO=fp@<сервер> ./faceplate/bin/faceplate console
```

`fp@<сервер>` — имя узла, который уже работает в кластере. Чтобы запустить узел в фоне, вместо `console` пишут `daemon`. Узел присоединяется к кластеру и работает с его базой. Переменная нужна только при первом запуске: дальше узел запускают как обычно, см. [«Запуск в окне»](#запуск-в-окне) и [«Запуск в фоне»](#запуск-в-фоне). Про панель **Сервера** см. [«Узлы кластера»](../nodes/nodes.md).

Если у узла уже есть своя база, `ATTACH_TO` не действует: узел запускается отдельным кластером со своей базой, сообщения об ошибке нет. Поэтому после запуска проверьте, что узел виден на панели **Сервера** у остальных узлов.

### Запуск после полной остановки кластера

Если остановлены все узлы кластера, при запуске они ждут друг друга: на любом из них могут быть данные, которых нет у остальных. В `logs/console.log` при этом повторяются строки `trying to connect to 'fp@<узел>' node` и `There were active nodes ['fp@<узел>'], when the node went down`.

Чтобы кластер запустился, первым запускают узел, остановленный последним, с переменной `FORCE_START`. Она разрешает узлу открыть базу, не дожидаясь остальных:

```bash
ulimit -n <предел>
env FORCE_START=true ./faceplate/bin/faceplate console
```

Для запуска в фоне вместо `console` пишут `daemon`. Остальные узлы после этого запускают как обычно, см. [«Запуск в окне»](#запуск-в-окне) и [«Запуск в фоне»](#запуск-в-фоне).

`FORCE_START` задают одному узлу и только на этот запуск. Узел с этой переменной считает свои данные самыми свежими, а изменения, которые попали только на другие узлы, теряются. Самые свежие данные — на узле, остановленном последним, поэтому переменную получает он.

# Заключение

Перед запуском задают предел открытых файлов не меньше 200 000. Узел запускают в окне (`console`) или в фоне (`daemon`): в окне узел работает, пока открыт терминал, в фоне — независимо от него. Запуск подтверждают строка `FACEPLATE STARTED` и открытая Studio. Консоль работающего узла открывают через `remote_console`, узел останавливают командой `stop`. Узел впервые присоединяют к кластеру запуском с `ATTACH_TO`, а после остановки всех узлов первым запускают с `FORCE_START` узел, остановленный последним.
