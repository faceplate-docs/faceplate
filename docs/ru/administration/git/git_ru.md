# Git в Faceplate: настройка подключения и обмен конфигурацией

Руководство для интеграторов Faceplate v4.0.7, которые подключают проект к Git, передают конфигурацию между стендами и управляют её версиями.

## Для чего нужен Git

Git сохраняет версии конфигурации Faceplate и передаёт их через удалённый репозиторий. Его используют при совместной разработке, подготовке испытаний и переносе согласованных изменений на другой стенд.

В обмене участвуют три состояния:

| Состояние | Что содержит | Как изменяется |
|---|---|---|
| Текущий проект | Конфигурация, которую инженер видит и редактирует в Студии | При сохранении объектов или применении полученных версий |
| Локальный репозиторий | Коммиты — зафиксированные версии на сервере Faceplate | При фиксации и операциях с историей |
| Удалённый репозиторий | Общая история на Git-сервере | При отправке коммитов другими участниками или этим стендом |

Обычный цикл публикации: сохранить объект в Студии → зафиксировать изменение → отправить коммит. Получение выполняется в обратном направлении: получить коммиты с сервера → применить их к конфигурации → проверить объекты в Студии.

Сохранение объекта ещё не создаёт коммит. Фиксация ещё не отправляет его на сервер. Получение изменений способно изменить или удалить объекты текущего проекта.

Контроль версий относится к конфигурации, а не к истории измерений. Репозиторий и разрешения подготавливает администратор Git-сервера.

### Где выполнять операции

1. Откройте **Меню** в Faceplate.
2. Выберите **Студия**.
3. Войдите в Студию своей учётной записью, если открылось окно входа.
4. Откройте **Меню** в Студии.
5. Выберите **Git**.

| Вкладка | Основные действия | Назначение |
|---|---|---|
| **Настройки** | **Клонировать**, **Инициализировать**, сохранение личных данных, сброс подключения, **Восстановить из CVS** | Подключение и управление локальной копией |
| **Локальные изменения** | **Зафиксировать**, **Загрузить**, **Merge request**, **Сброс** | Фиксация, отправка, запрос на слияние, отмена незафиксированных правок |
| **Удаленные изменения** | **Выгрузить**, **Откатить**, **Слияние веток** | Получение, работа с историей и перенос изменений между ветками |

В подписях интерфейса **Загрузить** означает отправить локальные коммиты на Git-сервер, а **Выгрузить** — получить изменения с сервера и применить их в Faceplate.

![Начальный экран настройки Git до подключения](./images/git-settings.png)

> [!NOTE]
> Пустые вкладки изменений не подтверждают совпадение проекта с сервером. В показанном интерфейсе нельзя полагаться на сравнение содержимого и подсветку файлов. Проверяйте сами объекты и историю нужной ветки на Git-сервере.

## Что подготовить

Перед первым подключением согласуйте состав переносимой конфигурации и способ восстановления доступа. Одной папки с учебными объектами недостаточно, чтобы ограничить все операции Git этой папкой.

| Что требуется | Что проверить до работы |
|---|---|
| Доступ в Студию | Учётная запись Faceplate может открывать Git и изменять необходимые объекты |
| Git на сервере Faceplate | Установлен и доступен процессу Faceplate; проверку выполняет администратор |
| Сетевой доступ | Именно сервер Faceplate имеет доступ к Git-серверу; вход в GitLab из браузера этого не доказывает |
| Удалённый репозиторий | Известны HTTPS-адрес, исходная ветка и ответственный за её содержимое |
| Реквизиты Git | Есть личные имя пользователя и пароль либо разрешённый сервером способ доступа через это поле |
| Разрешения Git | Для получения достаточно разрешения на чтение; отправка и запрос слияния требуют соответствующих разрешений сервера |
| Совместимая конфигурация | Репозиторий содержит экспорт Faceplate нужной структуры и объектов, а не произвольные исходные файлы |
| Резервная копия | Текущая конфигурация сохранена; известны порядок восстановления и учётная запись для входа после импорта |
| Состав публикации | В экспортируемой конфигурации нет неразрешённых адресов, реквизитов и посторонних объектов |

Логин в Faceplate, личные реквизиты Git и сессия веб-интерфейса GitLab решают разные задачи. Вход в один из этих сервисов не заменяет доступ к другому.

Введите пароль непосредственно в поле формы. Не помещайте его в URL, сообщение коммита, снимок экрана или описание обращения в поддержку. Если Git-сервер принимает токен вместо пароля, используйте только способ, подготовленный его администратором; отдельной настройки типа токена в форме нет.

### Как выбрать способ подключения

| Исходная задача | Действие | Что учитывать |
|---|---|---|
| Получить готовую конфигурацию из существующей ветки | **Клонировать** | Применяет конфигурацию из репозитория к текущему стенду; возможны создание, обновление и удаление объектов |
| Начать историю текущей конфигурации и связать её с подготовленным репозиторием | **Инициализировать** | Использует ветку main, выполняет обращение к существующей main и первоначальную отправку |
| Изменить личный пароль или автора коммитов при сохранении подключения | Сохранить личные данные в **Настройках** | URL, ветка и контекст остаются параметрами общего подключения |
| Подключить другой URL, ветку или контекст | Сбросить подключение и настроить заново | Сбрасываются локальная история и сохранённый Git-доступ всех пользователей |

**Инициализировать** не создаёт репозиторий на Git-сервере. Для этой процедуры заранее подготовьте совместимую ветку main. Не используйте пустой репозиторий как гарантированно подходящее исходное состояние.

### Общие параметры и личные данные

Удалённый URL, ветка и **Context folder** относятся к общему подключению на этом сервере Faceplate. После подключения они доступны для чтения. Имя пользователя, Email и пароль задаются пользователем. Сохранение этих полей не является проверкой связи с Git-сервером.

Имя пользователя и Email также участвуют в формировании автора коммита. Перед фиксацией после смены пользователя проверяйте, чьё имя будет указано в истории.

**Context folder** задаёт контекст проекта внутри экспортированной конфигурации. Это не каталог на компьютере пользователя. Пустое значение означает работу без контекста. Контекст позволяет получать изменения выбранной части проекта; он не изолирует глобальные данные при первоначальном клонировании и не ограничивает состав экспорта при фиксации.

### Учебные данные

НС01 — условное обозначение учебной насосной станции № 1. В Faceplate она представлена папкой проекта с именем НС01, которую администратор заранее подготавливает в учебном снимке конфигурации. Её поле **Заголовок** показывает этап работы; физических единиц у него нет.

| Данные | Значение в примерах |
|---|---|
| Адрес репозитория | https://git.example.org/training/ns01.git — вымышленный адрес; замените своим согласованным HTTPS-адресом |
| Исходная ветка | main |
| Ветка испытаний | ns01-trial |
| Контекст для отдельной станции | НС01 |
| Исходный заголовок НС01 | база |
| Заголовок после локального изменения | испытание |
| Заголовок после согласования | согласовано |
| Пример имени Git-пользователя | integrator01; замените своим логином |

Сценарий получения готовой НС01 начинается независимо от остальных. Администратор заранее подготавливает полный совместимый снимок с НС01 и известным доступом после импорта. Остальные сценарии используют его результат и дополнительные исходные данные, указанные в начале каждого этапа.

Для своего объекта замените имя НС01, контекст, сообщения и контрольные значения. Сохраните проверки области импорта, доступа и состава отправляемых данных.

## Получить готовую конфигурацию НС01

Лёгкий сценарий для интегратора: подключить существующую ветку main и проверить станцию в Студии.

| Исходные данные | Требуемое состояние |
|---|---|
| Git в Faceplate | Подключение ещё не настроено |
| Ветка main | Содержит совместимый полный снимок и папку НС01 с заголовком «база» |
| Учётная запись после импорта | Известна и имеет необходимые права в импортируемой конфигурации |
| Текущий проект | Сохранён в резервной копии; его замена согласована |

> [!WARNING]
> Clone без контекста может изменить проект, библиотеки, окружение, типы объектов, пользователей, группы и права. Отсутствующие в снимке объекты могут удаляться. Сохранение текущего администратора не гарантируется. До продолжения проверьте источник и возможность восстановления доступа.

### Клонировать ветку

1. Откройте **Git → Настройки** в Студии.
2. Нажмите **Клонировать**.
3. Выберите **yes** в вопросе о сохранении текущего проекта.
4. Сохраните проект в открывшемся диалоге экспорта.
5. Проверьте наличие сохранённого файла резервной копии перед заполнением формы Clone.

![Шаг 5 — поля формы клонирования до заполнения](./images/git-clone-form.png)

6. Укажите свой логин Git в поле **Имя пользователя**.
7. Оставьте **Email** пустым для использования автоматически формируемого адреса автора.
8. Введите реквизит доступа в поле **Пароль**.
9. Укажите согласованный адрес в поле **Удаленный URL-адрес**.
10. Введите main в поле **Название ветки**.
11. Оставьте **Context folder** пустым для полного учебного снимка.
12. Нажмите финальную кнопку **Клонировать** в заполненной форме.
13. Дождитесь завершения операции.

Ветка main не подставляется в пустую форму автоматически. Введите имя существующей ветки точно: неизвестное имя может означать создание новой локальной ветки, а не отказ из-за опечатки.

После резервного экспорта форма открывается сразу. Она открывается и при отмене диалога экспорта, поэтому её появление не подтверждает наличие копии. Если файл не сохранён, сначала завершите резервное копирование.

Если резервная копия уже подготовлена, первый вопрос можно отклонить кнопкой **no**, а продолжение подтвердить кнопкой **yes**. Такая последовательность открывает форму; перенос выполняет только финальная **Клонировать**. Два ответа **no** отменяют переход к клонированию.

### Проверить полученную станцию

1. Повторно откройте **Git → Настройки**.
2. Сверьте удалённый адрес и ветку main.
3. Проверьте, что контекст остался пустым.
4. Найдите папку НС01 в проектном дереве Студии.
5. Выберите её строку.
6. Нажмите **Редактировать**.
7. Проверьте значение **Заголовок**: ожидается «база».
8. Закройте форму без сохранения.
9. Проверьте вход подготовленной учётной записью в отдельной приватной сессии браузера.
10. Откройте **Локальные изменения**.
11. Откройте **Удаленные изменения**.

Критерий результата — ожидаемая НС01, параметры подключения и доступ к импортированной конфигурации. Пустой список изменений сам по себе эти проверки не заменяет. Время выполнения зависит от размера снимка и связи с Git-сервером; фиксированная длительность не задаётся.

## Опубликовать изменение НС01

Средний сценарий для интегратора: связать текущую конфигурацию с подготовленной main, изменить заголовок станции и передать версию коллегам.

| Исходные данные | Требуемое состояние |
|---|---|
| Результат предыдущего сценария | НС01 существует, заголовок «база», доступ работает |
| Удалённая main | Ответственный подтвердил совместимость с первоначальной публикацией текущего проекта |
| Резервная копия | Актуальна; все нужные локальные коммиты уже переданы на сервер |
| Разрешение на публикацию | Согласован весь экспортируемый состав, включая общие группы конфигурации |
| Учебный этап исключений | Отдельно согласовано удаление экспортированных файлов выбранной учебной группы каталогов |

### Повторно настроить подключение

> [!WARNING]
> **Сброс** в **Настройках** удаляет локальную Git-историю, параметры подключения и сохранённый Git-доступ всех пользователей этого стенда. Конфигурация Faceplate и удалённый репозиторий сохраняются. Не используйте это действие для обычного исправления пароля.

1. Откройте **Git → Настройки**.
2. Нажмите **Сброс** в настройках подключения.
3. Подтвердите сброс.
4. Проверьте наличие НС01 в Студии.
5. Проверьте её **Заголовок**: ожидается «база».
6. Вернитесь в **Git → Настройки**.
7. Нажмите **Инициализировать**.
8. Заполните **Имя пользователя** своим логином Git.
9. Укажите Email автора либо оставьте **Email** пустым.
10. Введите **Пароль**.
11. Укажите подготовленный **Удаленный URL-адрес**.
12. Нажмите финальную **Инициализировать** в форме.
13. Дождитесь завершения операции.

Init работает с main и включает первоначальную отправку. Это уже публикация конфигурации, поэтому проверка её допустимого состава требуется до нажатия финальной кнопки.

После успешной инициализации повторно откройте **Настройки**. Ожидаются согласованный URL и ветка main. На Git-сервере проверьте появление первоначальной фиксации и её автора. Если инициализация завершилась ошибкой, не переходите к фиксации НС01; разберите причину по разделу «Диагностика подключения и обмена». Параметры и локальная копия уже могли измениться до отказа. Перед повтором проверьте их состояние.

### Изменить и зафиксировать заголовок

1. Выберите папку НС01 в Студии.
2. Нажмите **Редактировать**.
3. Задайте **Заголовок** «испытание».
4. Сохраните форму кнопкой сохранения.
5. Повторно откройте свойства НС01.
6. Проверьте сохранённое значение «испытание».
7. Откройте **Git → Локальные изменения**.
8. Нажмите **Зафиксировать**.
9. Введите «НС01: испытание» в поле **message**.
10. Оставьте список **ignore** пустым для согласованного полного учебного состава.
11. Подтвердите форму кнопкой сохранения.
12. Дождитесь завершения фиксации.

Ожидаемый результат этого этапа — локальный коммит с сообщением «НС01: испытание». На удалённом сервере он появится только после отправки. Фиксация обращается к серверу за состоянием ветки, поэтому её нельзя считать гарантированно доступной без сети.

### Отправить коммит

> [!WARNING]
> При фиксации экспортируется конфигурация шире папки НС01. Перед отправкой ответственный за Git должен подтвердить изменённые и удалённые файлы локального коммита. Если встроенное представление не даёт проверить состав, остановите отправку до такого подтверждения.

1. Получите подтверждение допустимого состава локального коммита.
2. Нажмите **Загрузить** на вкладке **Локальные изменения**.
3. Дождитесь завершения отправки.
4. Откройте ветку main в веб-интерфейсе Git-сервера.
5. Найдите коммит «НС01: испытание».
6. Сверьте его автора и состав изменений.
7. Проверьте в Студии значение **Заголовок** у НС01: «испытание».

Проверка истории на сервере подтверждает публикацию. Сохранённое значение в Студии подтверждает текущее состояние объекта; это разные проверки.

### Проверить исключения на учебном составе

Исключения задаются только для конкретной фиксации. Они не являются правилом защиты уже существующих файлов на сервере. В частности, исключение группы может привести к удалению её ранее экспортированных файлов в новом коммите.

Выполняйте этот этап только на учебной конфигурации, где удаление экспортированной группы каталогов заранее согласовано. Исходная группа должна содержать только разрешённые учебные объекты. Папка НС01 остаётся в составе проекта.

1. Откройте **Локальные изменения** после отправки предыдущего коммита.
2. Нажмите **Зафиксировать**.
3. Введите «Учебная фиксация: исключены каталоги» в поле **message**.
4. Выберите **catalogs** в списке **ignore**.
5. Подтвердите форму кнопкой сохранения.
6. Передайте локальный коммит на проверку согласованных удалений.
7. Нажмите **Загрузить** только после подтверждения его состава.
8. Проверьте новый коммит и удаления группы в истории Git-сервера.
9. Проверьте, что заголовок НС01 остался «испытание».

Исключение проекта целиком не подходит для публикации изменения НС01. Исключение пользователей, групп или прав также не гарантирует сохранение их прежнего экспорта. Для рабочей конфигурации сначала согласуйте политику состава и её последствия с ответственным за Git.

## Подготовить ветку испытаний НС01

Сложный сценарий для ведущего интегратора: выделить ветку станции, сохранить личный доступ второго инженера и получить согласованную правку.

| Исходные данные | Требуемое состояние |
|---|---|
| НС01 | Результат публикации, заголовок «испытание» |
| Ветка по умолчанию на Git-сервере | main с нужной исходной конфигурацией |
| Имя новой ветки | ns01-trial ещё не занято |
| Расположение станции в снимке | НС01 находится непосредственно в корне экспортированного проекта |
| Пользователи | Две подготовленные учётные записи Faceplate с необходимыми правами; каждый инженер имеет свой доступ к Git |
| Удалённая правка для получения | Ответственный подготовит в ns01-trial заголовок «согласовано» после создания и публикации ветки |

### Подключить новую ветку с контекстом

Новая локальная ветка создаётся от ветки по умолчанию удалённого репозитория. Она не обязательно является main. До настройки подтвердите у ответственного, что исходная ветка содержит нужное состояние НС01.

> [!WARNING]
> Повторное подключение использует сброс и Clone с теми же последствиями для истории, доступа и конфигурации, что и предыдущие процедуры. **Context folder** не гарантирует сохранность общих библиотек, окружения и пользователей при Clone.

1. Сохраните актуальную резервную копию проекта.
2. Проверьте, что все нужные коммиты отправлены.
3. Сбросьте подключение через **Git → Настройки → Сброс**.
4. Откройте **Клонировать**.
5. Пройдите сохранение копии и проверьте сохранённый файл, как в первом сценарии.
6. Заполните личные реквизиты Git.
7. Укажите согласованный URL репозитория.
8. Введите ns01-trial в поле **Название ветки**.
9. Введите НС01 в поле **Context folder**.
10. Нажмите финальную **Клонировать**.
11. Дождитесь завершения операции.
12. Сверьте ветку ns01-trial и контекст НС01 в **Настройках**.
13. Проверьте НС01 в Студии: ожидается заголовок «испытание».
14. Отправьте новую ветку кнопкой **Загрузить** после проверки допустимого состава.
15. Проверьте наличие ns01-trial на Git-сервере.

Для НС01 непосредственно в корне экспортированного проекта вводите только НС01. Не добавляйте имя корня экспортного каталога или путь на сервере. Если станция расположена глубже, заранее согласуйте соответствующий контекст и отображение объектов после импорта.

Создание локальной ветки ещё не доказывает её наличие на сервере или настройку отслеживаемой ветки. Если дальнейшие операции сообщают об отсутствии upstream или не открываются настройки, остановитесь и передайте состояние ответственному за Git. Повторный Clone с другим случайным именем не устраняет причину.

### Сохранить личный доступ второго инженера

1. Войдите в Faceplate второй подготовленной учётной записью.
2. Откройте **Git → Настройки**.
3. Проверьте общий URL, ветку ns01-trial и контекст НС01.
4. Укажите личное **Имя пользователя** для Git.
5. Задайте **Email** автора либо оставьте поле пустым.
6. Введите свой **Пароль** Git.
7. Нажмите **Save** для личных данных.

Ожидаемый результат — сохранённые личные реквизиты при прежних общих параметрах подключения. Успешное сохранение не подтверждает аутентификацию на сервере. Реальный доступ проверяется следующей разрешённой операцией получения.

### Получить согласованный заголовок

До получения ответственный должен опубликовать в ns01-trial изменение заголовка НС01 на «согласовано». На текущем стенде не должно оставаться нужных незафиксированных правок.

1. Проверьте в веб-интерфейсе Git-сервера нужную ветку и опубликованную правку.
2. Откройте **Git → Удаленные изменения**.
3. Нажмите **Выгрузить**.
4. Подтвердите получение изменений.
5. Дождитесь завершения операции.
6. Откройте свойства НС01 в Студии.
7. Проверьте **Заголовок**: ожидается «согласовано».
8. Сверьте применённую правку с историей ns01-trial на Git-сервере.

При заданном контексте получение применяет изменения соответствующей части проекта. Общие библиотеки, окружение и локальные настройки этим контекстным получением не синхронизируются. Для их переноса нужен отдельно согласованный порядок.

## Завершить испытания и вернуть согласованную НС01

Сложный сценарий для ведущего интегратора: подготовить запрос на слияние и отработать разные способы возврата конфигурации. Этапы возврата выполняйте на учебном стенде с известными эталонами.

| Этап | Что должно быть подготовлено |
|---|---|
| Слияние веток и запрос | Ветка ns01-trial, совместимая удалённая ветка ns01-reviewed, целевая main и Git-сервер с поддержкой запросов через push options |
| Локальный сброс | Известный последний локальный коммит НС01 с заголовком «согласовано» |
| Восстановление локальной копии | Отдельный полный учебный снимок без контекста, рабочее отслеживание удалённой ветки и локальный неотправленный коммит |
| Возврат по истории | Два опубликованных эталона: A — «база», B — «испытание»; выбранная ветка допускает отправку нового коммита |
| Для всех этапов | Актуальная резервная копия, известный доступ после импорта и согласованный состав изменений |

### Подготовить запрос на слияние

**Слияние веток** переносит изменения выбранной удалённой ветки в текущую через rebase. Это не переключение активной ветки. До начала согласуйте совместимость изменений. Для примера подготовьте ns01-reviewed так, чтобы ожидаемый заголовок НС01 после переноса оставался «согласовано».

1. Завершите фиксацию и отправку текущих изменений ns01-trial.
2. Откройте **Удаленные изменения**.
3. Нажмите **Слияние веток**.
4. Выберите ns01-reviewed в списке удалённых веток.
5. Подтвердите действие кнопкой **Слияние веток**.
6. Дождитесь завершения переноса.
7. Проверьте НС01 в Студии: ожидается «согласовано».
8. Проверьте остальные объекты, затронутые согласованным изменением.
9. Откройте **Локальные изменения**.
10. Нажмите **Merge request**.
11. Проверьте запрос в веб-интерфейсе Git-сервера.
12. Сверьте исходную ns01-trial, целевую main и состав запроса.

Открытие списка веток уже получает сведения с сервера. **Merge request** запускает отправку с параметрами создания запроса; это не предварительный просмотр. Цель запроса — main. Создание запроса не означает, что main уже обновлена: дальнейшее согласование выполняется на Git-сервере.

При конфликте не считайте rebase успешным и не переходите к запросу. Встроенного пошагового редактора конфликтов здесь нет; порядок восстановления определяет ответственный за Git.

### Отменить незафиксированную правку

**Сброс** на вкладке **Локальные изменения** возвращает конфигурацию к текущему локальному коммиту. Он не удаляет уже созданные коммиты и не выбирает отдельные файлы.

1. Убедитесь, что последний локальный коммит содержит заголовок «согласовано».
2. Откройте свойства НС01 в Студии.
3. Измените **Заголовок** на «испытание».
4. Сохраните форму без фиксации в Git.
5. Откройте **Git → Локальные изменения**.
6. Нажмите **Сброс**.
7. Подтвердите потерю незафиксированных правок.
8. Дождитесь завершения операции.
9. Повторно откройте НС01.
10. Проверьте **Заголовок**: ожидается «согласовано».

Проверяется возврат к локальной версии. Он не доказывает совпадение с текущей удалённой веткой. Операция также обращается к серверу и применяет конфигурацию из локальной копии с учётом контекста.

### Восстановить конфигурацию из локальной копии

**Восстановить из CVS** повторно импортирует текущие локальные файлы конфигурации в Faceplate. Дата возле действия не является выбором произвольной исторической версии.

Для этого этапа ответственный заранее подготавливает полный учебный снимок без контекста: удалённый эталон A с заголовком «база» и локальный коммит B с заголовком «испытание», который ещё не отправлен. Отслеживание удалённой ветки должно работать. Не переиспользуйте контекстный стенд без такой подготовки.

> [!WARNING]
> Восстановление выполняется без контекста и без выбора исключений. Оно может создать, обновить и удалить объекты общей конфигурации и изменить доступ. Одно положительное подтверждение сразу запускает импорт.

1. Проверьте, что локальная копия B содержит разрешённый полный состав.
2. Измените только **Заголовок** НС01 в Студии на «согласовано».
3. Сохраните форму без нового Commit и без Push.
4. Заново откройте **Git → Настройки**, чтобы обновить состояние действия.
5. Нажмите **Восстановить из CVS**, если оно доступно.
6. Подтвердите восстановление.
7. Дождитесь завершения импорта.
8. Проверьте НС01: ожидается заголовок «испытание» из локальной копии B.
9. Проверьте согласованный полный набор объектов и доступ пользователей.

Действие зависит от наличия локальных коммитов сверх отслеживаемой удалённой истории. После отправки диапазон может стать пустым, и кнопка будет недоступна. Для обычной незафиксированной правки используйте локальный **Сброс**, если его результат соответствует вашей задаче.

### Вернуть состояние из истории

**Откатить** создаёт новый коммит со состоянием выбранной версии. Выбранный коммит сохраняется вместе со своими изменениями; возвращаются к его результату, а не отменяют именно его. Более поздние коммиты остаются в истории.

Для примера подготовьте опубликованные A с заголовком «база» и B с заголовком «испытание», где B — текущая версия. Выбор A должен привести к новому коммиту C с заголовком «база».

> [!WARNING]
> Возврат по истории автоматически отправляет новый коммит на Git-сервер. Перед окончательным подтверждением проверьте ветку, выбранный эталон и допустимый состав возврата. Отдельной команды Push для завершения этого действия не требуется.

1. Откройте **Git → Удаленные изменения**.
2. Нажмите **Откатить**.
3. Найдите эталон A по идентификатору, сообщению и автору в истории.
4. Выберите его строку.
5. Подтвердите выбор кнопкой сохранения формы.
6. Подтвердите предупреждение о потере неотправленных изменений.
7. Дождитесь завершения возврата и отправки.
8. Откройте НС01 в Студии.
9. Проверьте **Заголовок**: ожидается «база».
10. Найдите новый отменяющий коммит C в истории выбранной ветки на Git-сервере.
11. Проверьте, что B остаётся в истории.
12. Сверьте остальные объекты, затронутые возвратом.

Применение выполняется по различиям выбранных версий. Посторонние правки текущей конфигурации за пределами этих различий могут остаться. Уведомление об окончании операции не заменяет проверку объектов и удалённой истории.

Если отправка завершилась ошибкой, локальная конфигурация и новый коммит уже могли измениться. Перед повтором сначала сверяйте оба состояния; повторное нажатие не является безопасной проверкой связи.

## Справочник полей и состояний

### Параметры подключения

В новой форме поля пусты. Значения обязательных полей вводит пользователь; автоматическая подстановка main в Clone отсутствует.

| Поле | Обязательность и начальное значение | Назначение и ограничения |
|---|---|---|
| **Имя пользователя** | Обязательно; пусто | Логин доступа к Git; также используется для автора коммитов. Не заменяет учётную запись Faceplate |
| **Email** | Необязательно; пусто | Адрес автора. При пустом поле формируется адрес вида integrator01@faceplate.io из заданного логина |
| **Пароль** | Обязательно; пусто, ввод скрыт | Реквизит доступа для Git-сервера. Не помещайте его в остальные поля |
| **Удаленный URL-адрес** | Обязательно; пусто | Адрес существующего репозитория. Используйте согласованный HTTPS-адрес без встроенного пароля. После подключения — только чтение |
| **Название ветки** | Обязательно для Clone; пусто | Точное имя существующей или новой локальной ветки. Init использует main без этого поля. После подключения — только чтение |
| **Context folder** | Необязательно; пусто | Контекст внутри проекта. Пусто — без контекста. После подключения — только чтение |

При непустом Email проверка формата принимает окончание домена из двух–четырёх латинских букв. Если корректный корпоративный адрес не проходит такую проверку, не подбирайте вымышленный адрес; согласуйте вариант с администратором либо используйте пустое поле и учитывайте автоматически сформированного автора.

Заполненная форма проверяет наличие обязательных значений, но не доказывает существование репозитория, правильность ветки или разрешение на отправку. Эти условия проверяются при реальной Git-операции.

### Сообщение и исключения фиксации

| Поле формы **Зафиксировать** | Значение |
|---|---|
| **message** | Обязательное сообщение о конкретном изменении; пример: «НС01: испытание» |
| **ignore** | Список исключаемых групп для этой фиксации; изначально ничего не выбрано |

Значения списка **ignore** отображаются техническими названиями групп:

| Значение в списке | Группа конфигурации |
|---|---|
| **global_libraries** | Общие библиотеки |
| **environment** | Окружение |
| **primitives** | Примитивы |
| **catalogs** | Каталоги |
| **prototypes** | Прототипы |
| **usergroups** | Группы пользователей |
| **users** | Пользователи |
| **project** | Проект, включая НС01 |
| **user_rights** | Права на экраны |

Исключённая группа может исчезнуть из экспортированной версии. Проверяйте удаления так же, как добавления и изменения. При следующем полном экспорте ранее исключённые данные могут снова попасть в состав; список не задаёт постоянную политику исключений.

### Выбор ветки и версии

| Форма | Что выбирает пользователь | Что проверить |
|---|---|---|
| **Слияние веток** | Удалённую ветку из полученного с сервера списка | Это источник изменений для текущей ветки; пустой выбор недопустим |
| **Откатить** | Строку истории с идентификатором коммита | Сообщение, автора, дату и известное состояние объектов; выбор не должен опираться только на номер строки |

В истории используются колонки **Commit hash**, **Commit date**, **Message**, **Author**. Дата коммита представлена в UTC. Для однозначного согласования версии сохраняйте её идентификатор вместе с сообщением.

### Как различать операции возврата

| Действие | Что меняет | Что проверить после завершения |
|---|---|---|
| **Настройки → Сброс** | Удаляет локальную историю Git, подключение и сохранённый Git-доступ всех пользователей | Проект сохранён, подключение нужно настроить заново |
| **Локальные изменения → Сброс** | Возвращает конфигурацию к текущему локальному коммиту с учётом контекста; удаляет незафиксированные правки | Контрольные значения соответствуют локальному коммиту; история коммитов сохранена |
| **Восстановить из CVS** | Импортирует текущую локальную копию без контекста и исключений | Полный состав, значения объектов и доступ соответствуют подготовленному локальному эталону |
| **Откатить** | Создаёт коммит со состоянием выбранной версии, применяет различия и автоматически отправляет результат | Нужные объекты восстановлены; новый коммит появился в удалённой ветке |

### Состояния подключения

| Наблюдение | Что оно подтверждает | Чего дополнительно требует проверка |
|---|---|---|
| Открыты **Клонировать** и **Инициализировать**, параметры ещё не заданы | Исходное состояние настройки | Подготовить источник и личный доступ |
| Отображаются URL, ветка и контекст | Сохранены параметры общего подключения | Проверить связь реальной разрешённой операцией |
| Личные данные сохранены через **Save** | Данные записаны для пользователя | Проверить аутентификацию и разрешение на нужную операцию |
| Коммит создан локально | Версия зафиксирована на сервере Faceplate | Проверить отправку и состав удалённой истории |
| **Восстановить из CVS** недоступна | Нет доступного состояния действия на момент открытия настроек | Проверить локальные коммиты сверх upstream и наличие отслеживания; это не признак отсутствия резервной копии |
| Списки изменений пусты | Представление не показывает элементов | Проверить объекты и Git-историю; синхронизация этим не доказана |

## Диагностика подключения и обмена

При ошибке сохраните текст сообщения, имя операции, текущую ветку и время. Не прикладывайте пароль, токен, содержимое поля доступа или полный снимок формы с личными данными.

| Симптом | Проверка и возможная причина | Действие | Контроль восстановления |
|---|---|---|---|
| Финальная кнопка Clone или Init неактивна | В форме не заполнено обязательное поле | Проверьте логин, пароль, URL; для Clone также имя ветки | Кнопка становится доступна; доступ к серверу проверяется отдельно |
| Email отклоняется | В **Email** не проходит встроенная проверка формата | Исправьте адрес либо согласованно оставьте поле пустым | Данные сохраняются; автор последующего коммита ожидаемый |
| Нет Git на сервере | Недоступна установленная серверная программа Git | Передайте сообщение администратору Faceplate | Та же разрешённая операция запускается без ошибки отсутствия Git |
| Репозиторий недоступен | Проверьте URL и доступность Git-сервера именно с сервера Faceplate | Исправьте адрес или сетевой доступ через ответственного администратора | Получение разрешённой ветки проходит |
| Отказ доступа к Git | Проверьте личные реквизиты текущего Faceplate-пользователя и разрешение Git-сервера | Исправьте личные данные и нажмите **Save**; затем повторите разрешённую операцию | Успешна сама операция, а не только сохранение полей |
| Commit не проходит при заполненном сообщении и пустом списке исключений | Проверьте **message**, **ignore** и точный текст ошибки формы или операции | Передайте ошибку поддержке; не выбирайте случайную группу ради обхода, поскольку это меняет состав версии | Создан коммит с нужным составом без непредусмотренных исключений |
| Commit сообщает о различиях с удалённой веткой | На сервере есть новые изменения либо предыдущий локальный коммит ещё не отправлен | Сначала сверяйте историю: отправьте согласованный локальный коммит или получите нужные удалённые изменения | Состояния веток согласованы, новая фиксация проходит |
| Pull не выполняется из-за локальных изменений | Несохранённые или незафиксированные правки мешают применению | Сохраните нужные данные и согласуйте фиксацию либо возврат к локальной версии | Получение проходит, НС01 имеет ожидаемый заголовок |
| Конфликт при получении или rebase | Изменения сторон несовместимы | Остановите дальнейшие публикации; передайте состояние ответственному за Git | Конфликт устранён, проверены объекты и история перед продолжением |
| После импорта отсутствует объект или потерян доступ | Проверьте исходную ветку, контекст и состав снимка | Используйте заранее согласованный порядок восстановления и известную учётную запись из копии | Вход и контрольные объекты восстановлены |
| После создания новой ветки ошибка upstream | Не настроено ожидаемое отслеживание удалённой ветки | Передайте точный текст ошибки ответственному за Git; не пересоздавайте подключение случайными параметрами | Настройки открываются и операции с нужной веткой работают |
| **Восстановить из CVS** недоступна после отправки | Может не остаться локальных коммитов сверх upstream | Заново откройте настройки; выбирайте возврат по нужной задаче | Действие соответствует подготовленному эталону, без лишнего нового коммита ради кнопки |
| Операция сообщает об ошибках отдельных объектов | Импорт мог выполниться частично | Сохраните список объектов и причин; сверяйте применённую конфигурацию с копией | Проверен полный согласованный набор, а не только сообщение об окончании |
| Merge request не появился | Проверьте разрешения, поддержку push options, исходную ветку и main | Передайте сообщение Git-сервера ответственному; не считайте отправку созданным запросом | В Git-сервере виден запрос с ожидаемыми ветками и составом |
| Rollback изменил проект, но отправка не завершилась | Локальный коммит мог быть создан до ошибки Push | Сверьте локальный результат и удалённую историю перед любым повтором | Нужный коммит и значения объектов согласованы на обеих сторонах |

Если сообщение содержит путь объекта и причину, считайте его указанием на возможный частичный импорт. После исправления причины проверяйте все затронутые объекты. Повторение команды без такой проверки может скрыть промежуточное состояние.

## Ограничения

- Общая конфигурация подключения и локальная история принадлежат стенду; это не независимый репозиторий каждого инженера.
- Контекст не ограничивает экспорт при Init и Commit и не является полной изоляцией Clone. Restore применяется без контекста.
- Штатного выбора отдельных файлов для локального сброса и произвольной даты для Restore нет.
- Редактирование URL, ветки и контекста существующего подключения требует повторной настройки. Интерфейс не предоставляет отдельные операции переименования или удаления ветки.
- Исключения фиксации не заменяют проверку конфиденциальности и согласование удалений.
- Для описанного подключения используйте согласованный HTTPS-доступ. Отдельного мастера настройки SSH-ключей нет.
- Фиксация и локальный сброс обращаются к серверу; автономную работу этих действий без сети не предполагайте.
- Встроенные представления не заменяют проверку содержимого коммита. Уведомление об окончании не гарантирует успешное применение всех объектов.
- Ошибка публикации не означает, что все предшествующие локальные изменения автоматически отменены. Перед повтором сверяйте проект и историю.
- Запрос на слияние направляется в main; поддержки сервера и прав пользователя нужно добиться до нажатия **Merge request**.
